# 通知平台准备指南（飞书 / 钉钉 / 企业微信）

配置「通知平台身份」前，每平台需要准备三类信息：**群机器人 Webhook**（必填，发送通道）、**用户唯一 ID**（启用通知时必填，@ 提及对象）、**成员拉取凭证**（可选，用于「拉取成员」按钮一键拉取通讯录成员列表供搜索选择；不填则手动粘贴 ID）。

## 总览

| 平台 | Webhook 来源 | 用户唯一 ID 是什么 | 拉取凭证（可选） | @所有人 |
|---|---|---|---|---|
| 飞书 | 群设置 → 群机器人 → 添加自定义机器人 | **Open ID**（`ou_` 开头） | 自建应用 App ID + App Secret | 填 `all`（群需开启 @所有人） |
| 钉钉 | 群设置 → 机器人 → 添加自定义机器人（加签） | 企业内 **userid**（staffId，无固定前缀） | 企业内部应用 AppKey + AppSecret | 由通知系统发送，无需配置 |
| 企业微信 | 群设置 → 添加群机器人（消息推送） | 成员 **userid**（= 通讯录「账号」） | corpid + 自建应用 Secret | 手动加 `@all` 到 ID 列表 |

## 飞书

### 1. Webhook（必填）
群聊 → 设置 → 群机器人 → 添加机器人 → **自定义机器人**。创建后复制 Webhook 地址。
若开启了「签名校验」，把密钥填进「签名密钥」字段。

### 2. 用户唯一 ID（必填，`ou_` 开头的 Open ID）
> 本插件只对 `ou_` 前缀的 ID 生成真正的 @；其他值只以纯文本展示。

无拉取凭证时的手动获取途径（从易到难）：
1. **API 调试台一键复制（推荐）**：[open.feishu.cn/api-explorer](https://open.feishu.cn/api-explorer) 登录企业账号（名下无应用需先创建一个自建应用）→ 「发送消息」接口 → `user_id_type` 设为 `open_id` → 点「快速复制 open_id」→ 搜索成员 → 复制。
2. **自建应用 + 手机号/邮箱换 ID**（开发者）：应用开通「通过手机号或邮箱获取用户 ID」权限后调 `contact/v3/users/batch_get_id`。

### 3. 拉取凭证（可选，推荐配置）
- **在哪建**：[开放平台开发者后台](https://open.feishu.cn) → 创建企业自建应用。
- **App ID / App Secret**：应用「凭证与基础信息」页。
- **要开通的权限**（应用「权限管理」→ 按权限码搜索申请 → 发布版本经管理员审批）：

| 权限 | 权限码 | 用途 |
|---|---|---|
| 获取通讯录基本信息 | `contact:contact.base:readonly` | 调用「子部门列表 / 部门直属用户列表」两个接口（**开出任一项同类权限即可**，如 `contact:contact:readonly_as_app`） |
| 获取用户基本信息 | `contact:user.base:readonly` | 返回成员**姓名**字段（不开启则拉不到名字，只剩 ou_ ID） |

- **通讯录权限范围**：按应用实际的「通讯录权限范围」拉取——**部分授权范围即可使用**（v0.5.1 起按授权部门遍历，不再要求全员权限；更早版本查根部门会报 `40004 no dept authority`）。要拉全企业成员就把权限范围设为「全部成员」。拉取结果为空时优先检查权限点是否开通、版本是否已发布生效。
- 拉到的 open_id 与 webhook 机器人的 @ 直接兼容（不要求同应用）。

## 钉钉

### 1. Webhook（必填）
群聊 → 设置 → 机器人 → 添加机器人 → **自定义（通过 Webhook 接入）**，安全设置选「加签」并把密钥填进「签名密钥」字段（本插件按加签方式发送）。

> 官方已标注「自定义机器人产品即将下线」：存量机器人不受影响；若你的组织无法新建自定义机器人，需要改用企业内部应用机器人方案。

### 2. 用户唯一 ID（必填，企业内 userid）
不是手机号、不是 unionId、也不是 `$:LWCP_v1:$` 开头的加密 ID。

无拉取凭证时的手动获取途径：
1. **管理后台直接看（管理员，零开发）**：[oa.dingtalk.com](https://oa.dingtalk.com) → 通讯录 → 成员管理 → **单击员工姓名**即见 UserID。
2. **手机号 @ 替代**：钉钉支持 `at.atMobiles` 手机号 @，但本插件当前只透传 userid。

### 3. 拉取凭证（可选）
- **在哪建**：[open-dev.dingtalk.com](https://open-dev.dingtalk.com) → 应用开发 → 创建**企业内部应用**（H5 微应用即可）。
- **AppKey / AppSecret**：应用「凭证与基础信息」页。
- **要开通的权限**（应用「权限管理」→ 搜索并申请，企业内部应用无需审批即时生效）：

| 权限点 | 用途 |
|---|---|
| 通讯录部门信息读权限 | 调用「获取子部门列表」（`department/listsub`），遍历部门树 |
| 通讯录部门成员读权限 | 调用「获取部门用户列表」（`v2/user/list`），拉取成员 userid + 姓名 |

- **授权范围**：把目标员工所在**部门加入应用授权范围**（默认仅本部门）——否则接口报 `errcode 50002`（不在授权范围）。要拉全企业就把根部门（或全部部门）加入授权范围。
- 离职员工不在拉取结果中。

## 企业微信

### 1. Webhook（必填）
群聊 → 右上角 → 添加群机器人（现名「消息推送」）。创建后复制 Webhook 地址。此平台无签名密钥。

### 2. 用户唯一 ID（必填，成员 userid = 通讯录「账号」）
不是姓名、不是手机号、不是微信 ID。

无拉取凭证时的手动获取途径：
1. **管理后台看「账号」（管理员）**：[work.weixin.qq.com/wework_admin](https://work.weixin.qq.com/wework_admin) → 通讯录 → 成员详情页 → 「账号」字段。
2. **手机端**：企业微信 App → 通讯录 → 右上角编辑 → 选成员 → 编辑成员，同样能看到账号。

### 3. 拉取凭证（可选）
- **在哪建**：管理后台 → 应用管理 → **自建** → 创建应用。
- **corpid**：管理后台「我的企业」→「企业信息」→ 企业 ID；**Secret**：自建应用详情页。
- **要开通的权限**：企微**没有按接口的权限码体系**——`department/list` 与 `user/simplelist` 都按自建应用的「**可见范围**」过滤。配置入口：管理后台 → 应用管理 → 应用 → 自建 → 点进应用，详情页**顶部基础信息区的「可见范围」行**，点「修改」选**全部部门**（或至少覆盖目标成员所在部门），**即时生效**无需发布审批；手机端路径为 工作台 → 管理企业 → 应用管理 → 选应用 → 修改可见范围。
- 注意：`user/list_id` 接口仅通讯录同步 secret 可用，本插件用自建应用 secret 走 `user/simplelist`，无需通讯录同步助手。

## 共通注意事项

1. **@ 只对机器人所在群的成员生效**，且三平台的 @ 失败几乎都是**静默**的（飞书显示名字文本、钉钉脱敏、企微无提示）——配置后请用「测试发送」让被 @ 人在客户端确认真的收到提醒。
2. **限流**（发送侧硬约束）：飞书单机器人 100 次/分钟且 5 次/秒；钉钉 20 条/分钟（超限封 10 分钟）；企微 20 条/分钟。
3. **Webhook 地址 = 无限发送权限**，按机密对待；泄露请到群里移除机器人重建。
4. 企微的 markdown 通知通过 content 内 `<@userid>` 扩展语法 @ 成员（v0.5.0 起生效；更早版本企微 @ 不生效）。
5. 拉取凭证仅用于成员选择，**不参与通知投递**；保存后凭证与 Webhook 一样明文回显（管理面已鉴权），审计日志中自动脱敏。
