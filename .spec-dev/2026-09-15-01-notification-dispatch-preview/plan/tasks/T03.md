- 测试：`notification_keeper_test.go`

**接口**：
- 消费：`keeperClient.authenticatedRequest`；已有 `GET /api/v1/usage/api-keys/settings`（`keeper_client.go` 已请求该路径）
- 产出：`func (s *keeperStatsSource) collectAuthChannels(ctx context.Context, apiKey string) (rows []channelStats, totals map[string]int64, err error)`；`channelStats.Identity string`（composition key）；全局 `apiKey==""` 不过滤；Key 级用 settings 的 `apiKey` 字段对齐后带 `api_key_id`；占比 `Share = keyTokens/totals[identity]`，totals 来自不过滤 analysis 的同 identity `TotalTokens`

`TestCollectAuthChannelsKeyLevelExcludesOtherKeys`：过滤后正文行只有 Codex，不得出现另一 API Key label（Scenario：Key 级不含其他 Key）。
`TestShareUsesChannelWideDenominator`：K 800000 / 全站 2000000 → Share=0.4（Scenario：占比用渠道全站分母）。
`TestAPIKeyMappingFailureClosedCode`：settings 无匹配 → error 闭码，不返回全站 api_key_composition。

**步骤 2：运行确认失败**

**步骤 3：写最小实现**
