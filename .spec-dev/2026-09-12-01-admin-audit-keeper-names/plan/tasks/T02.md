**步骤 3：最小实现**

在 dispatch 的四个已知 mutation 分支进入 withAuditedManagement；保留原handler用于实际校验/修改。管理handler用前后快照构造 auditResult，非法JSON也先进入审计门再返回原400，不记录原body。
关键执行顺序如下；auditEventForRequest(req pluginapi.ManagementRequest, before State) auditEvent 在本文件实现，只取action/object_type/object_ref/actor白名单；auditStateResult(req pluginapi.ManagementRequest,before State,after State,resp pluginapi.ManagementResponse) auditResult 在本文件以真实快照生成结果。所有既有handler的run闭包先后读取快照并返回此结果：
~~~go
func withAuditedManagement(req pluginapi.ManagementRequest,
    run func() (pluginapi.ManagementResponse, auditResult)) pluginapi.ManagementResponse {
    managementMutationMu.Lock()
    defer managementMutationMu.Unlock()
    before, _ := loadedStateSnapshot()
    event := auditEventForRequest(req, before)
    ticket, err := beginAudit(stateFilePath(), event)
    if err != nil { return managementError(http.StatusServiceUnavailable, "audit_unavailable") }
    response, result := run()
    event.Outcome = result.Outcome
    event.Changed = result.Changed
    event.Changes = result.Changes
    event.ErrorCode = result.ErrorCode
    err = finishAudit(ticket, event)
    var body map[string]json.RawMessage
    if decodeErr := json.Unmarshal(response.Body, &body); decodeErr != nil {
        return managementError(http.StatusInternalServerError, "invalid_management_response")
    }
    meta := map[string]any{"operation_id": ticket.ID, "recorded": err == nil}
    if err != nil { meta["error_code"] = "audit_write_failed" }
    body["audit"], _ = json.Marshal(meta)
    response.Body, _ = json.Marshal(body)
    return response
}
~~~
本票全部run分支维持现有JSON对象响应不变量，测试覆盖每种失败对象。Finish负责移除当前in-flight标记并固定ticket目标；不能在Finish失败后再次调用run。若增加panic保护，仅记录unknown并清理in-flight后继续原错误传播，不执行补偿业务操作。
handlePluginReconfigure 从解析成功至配置/state交换期间获取同一 managementMutationMu；不拿此锁的推理读取维持旧快照，规则/配置内部锁在Keeper IO前释放。reset名称服务在T03接入。
脱敏仅投影字段；Key对象使用完整SHA-256及掩码，别名/规则白名单字符串中的已知Key、当前CPA认证header秘密、Keeper密码替换；不要日志fmt整对象/完整URL。
