**步骤 3：最小实现**

api.ts补CpaAuthFile.auth_index/name/type可选字段，保留id；新增响应类型与三方法（沿call原有HTML对称解码）：
~~~ts
getKeeperAuthNames: () => call<KeeperAuthNamesResponse>('GET', '/keeper/auth-names'),
refreshKeeperAuthNames: () => call<KeeperAuthNamesResponse>('POST', '/keeper/auth-names/refresh'),
patchKeeperAuthName: (authIndex: string, alias: string) =>
  call<KeeperAuthNameUpdateResponse>('PATCH', '/keeper/auth-names', { auth_index: authIndex, alias }),
~~~
keeperAuthNames.ts产出findKeeperAuthName(file:CpaAuthFile,names:readonly KeeperAuthName[]):KeeperAuthName|undefined，精确匹配auth_index且只匹配Codex auth-file；多匹配返回undefined并由状态文案显示异常。使用简单filter，不改auth_ids。
KeysPanel独立加载CPA目录与Keeper名称，失败互不清空；将names状态传给ChannelTargetEditor（新增可选Props以保留其他现行调用）。搜索加入display_name、原label/name/id；列表展示显示名+原文件标识。总定向开关只控制选择，新独立名称编辑不改变开关。
KeeperAuthNameEditor输入框label为“认证自定义名称”，按钮为“同步到 Keeper”。说明“立即保存到 Keeper，取消绑定不会撤销”；字符计数使用Array.from(alias).length，后端仍权威校验。提交防重复；捕获索引/会话/输入版本，只在同一编辑版本回显。成功更新本地名称映射，失败不清输入；unknown显示“同步结果未确认，请刷新名称核对”，不自动retry。
响应audit.recorded=false时保留ready/unknown实际结果且明显显示审计警告，不能只有普通成功Toast。
新增CSS只约束名称换行/按钮布局，保留桌面860px和视口减32px限制。更新api.test验证snake_case与HTML还原。
