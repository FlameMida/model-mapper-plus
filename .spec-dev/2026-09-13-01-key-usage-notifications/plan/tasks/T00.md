### 任务 0：建立隔离工作区

**步骤 1：检测已有隔离**

运行：`git rev-parse --git-dir` 与 `git rev-parse --git-common-dir`
两者不同、且 `git rev-parse --show-superproject-working-tree` 无输出（排除 submodule）
→ 已在隔离工作区，只跳过步骤 2 的创建，仍执行下面的绑定、步骤 3 与完成状态保存。

在创建前记录实际来源工作区绝对路径、来源分支与 HEAD；创建后记录实际实施工作区与分支。复用时从原隔离机制的记录核对来源，不能由 common-dir 推算来源工作区、假定来源为 main 或把复用资源改为本计划所有。用现有 append-only `notes` 保存这些真实值、created/inherited 归属及移交方式；`resources` 中复用行写保留/移交回执，不能预填删除命令。无法核实的来源明确记未知，不能据此生成合并命令。

**步骤 2：建立 worktree**

有原生 worktree 工具（如 EnterWorktree）或 using-git-worktrees skill 时优先使用（Codex 无原生 worktree 工具，直接走下面的手工路径）；否则手工降级：
确认 `.worktrees/` 已被忽略（`git check-ignore -q .worktrees`，未忽略先加入 `.gitignore` 并提交），然后

```bash
git worktree add .worktrees/plan-2026-09-13-01-key-usage-notifications -b plan-2026-09-13-01-key-usage-notifications
cd .worktrees/plan-2026-09-13-01-key-usage-notifications
```

分支名对齐计划：`plan-2026-09-13-01-key-usage-notifications`。若采用其他实际路径/分支名，更新 progress.yaml 的 resources 行与 notes。

**步骤 3：安装依赖并验证基线**

先读取项目声明的工具/命令、锁文件和已有环境；已就绪不强制重装。Go 侧依赖随各任务 `go get`；前端依赖在 T01 升级——本任务只需保证 `pnpm --dir web install`（或项目实际安装命令）可跑通。

按计划头部「相关测试范围」运行基线验证（有声明 → 只跑声明范围）：

```bash
go vet . && go test . -count=1 -run '^Test(Notification|KeyBinding|Management|Audit|Host|Plugin)'
npm --prefix web run typecheck && npm --prefix web test
```

预期：vet 干净；既有测试全绿（`^Test(Notification|…)` 中 Notification 前缀当前无匹配属预期，Go 的 -run 正则匹配不到时输出 `[no test files]`/ok，不是失败）。声明命令执行报错或工具不可用 → 改跑本特性自有测试文件并注明声明已失效、建议修订计划，**不回退完整测试套件**。基线测试失败 → 停下报告，先问再继续。

**步骤 4：保存完成状态**

将已验证的实际基线 SHA（`git rev-parse HEAD`）写入 `progress.yaml` 的 T00.commit，状态 `completed`、`current: T01`；状态写入采用同目录临时文件 + rename，保留原 tasks/notes/resources；状态提交独立于它引用的实际基线提交。所有 git 命令在实施工作区仓库根执行，路径用完整仓库根相对路径：

```bash
git add .spec-dev/2026-09-13-01-key-usage-notifications/plan/progress.yaml
git commit -m "chore(T00): worktree ready, baseline <sha>"
```
