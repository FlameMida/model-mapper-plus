**步骤 3：写最小实现**

`notification_types.go`：按接口块逐字段定义全部类型与常量（package main；JSON tag 与接口块签名一致，`omitempty` 只出现在接口块标了 `omitempty` 的字段上）。校验函数实现口径：

- `validateNotificationEntity(n, path)`（所有错误带 `path` 前缀与字段名）：名称 trim 非空；`modules` 非空、kind 在七枚举内、无重复 kind；`daily/monthly/half_year/yearly` 必须带合法 `Period`、`window_5h/weekly/reset_cards` 的 `Period` 必须为空；`schedule != nil` 时：interval → `1<=Interval<=31*86400` 且 `Time` 为空；monthly → `Time` 合法 `HH:MM:SS`（用 T03 `parseDayTime` 的四段格式口径，实现本地 `validDayTime` 或直接复用）；yearly → `1<=Month<=12`、`1<=Day<=31` 且 `Time` 合法（2/29 合法性由调度跳过，校验放行）；`platforms` 无重复 kind、枚举合法；`Enabled` 平台 `Webhook` 非空（http/https 前缀）且 `UserIDs` 至少一条非空 → 否则 `path.platforms[i]: user_ids is required`；`PlatformWeCom` 的 `SignSecret` 非空 → `sign_secret not supported for wecom`。
- `validateNotificationSettings(s)`：`GlobalDefault.Name` 非空 + `validateNotificationEntity(&s.GlobalDefault, "notifications.global_default")`。
- `validateKeyNotifications(st)`：逐 binding 逐通知 `validateNotificationEntity(n, "key_bindings[i].notifications[j]")` + 同 binding 内 trim 后名称唯一（错误锚定 `key_bindings[i].notifications[j]`）；`Notifications` 为空 → 跳过（走全局回退，无约束）。在 `validateState` 的 key 循环内对每条 binding 调用同一实体校验（提取 `validateKeyNotificationsEntity(&b)` 供两处复用），并对 `st.Notifications != nil` 时调 `validateNotificationSettings`。

func cloneNotifications(in []Notification) []Notification {
	if in == nil { return nil }
	out := make([]Notification, len(in))
	for i := range in {
		out[i] = in[i]
		out[i].Modules = append([]ModuleConfig(nil), in[i].Modules...)
		out[i].Platforms = clonePlatformIdentities(in[i].Platforms)
		if in[i].Schedule != nil { s := *in[i].Schedule; out[i].Schedule = &s }
	}
	return out
}
func clonePlatformIdentities(in []PlatformIdentity) []PlatformIdentity {
	if in == nil { return nil }
	out := make([]PlatformIdentity, len(in))
	for i := range in { out[i] = in[i]; out[i].UserIDs = append([]string(nil), in[i].UserIDs...) }
	return out
}
