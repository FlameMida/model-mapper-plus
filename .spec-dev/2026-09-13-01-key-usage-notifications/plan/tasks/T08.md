`notification_service.go` 核心：

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"sync"
	"time"
)

type serviceDeps struct {
	Now        func() time.Time
	Source     *keeperStatsSource
	NewAdapter func(PlatformIdentity) (platformAdapter, error)
	Store      *notificationStore
	Tick       time.Duration
}

type notificationStatus struct {
	Running     bool   `json:"running"`
	ErrorCode   string `json:"error_code,omitempty"`
	Revision    uint64 `json:"revision"`
	PendingJobs int    `json:"pending_jobs"`
	NextFire    string `json:"next_fire,omitempty"`
}

type notificationService struct {
	deps     serviceDeps
	state    State
	cancel   context.CancelFunc
	wg       sync.WaitGroup
	mu       sync.Mutex
	status   notificationStatus
	lastFire time.Time
}

var activeNotification struct {
	sync.Mutex
	svc *notificationService
}
```

- `startNotificationService(cfg, st, store, deps)`：`deps.Now` 缺省 `time.Now`、`deps.Tick` 缺省 15s、`deps.NewAdapter` 缺省 `buildAdapter`、`deps.Store == nil` → error（上层转 `notificationStatus.ErrorCode="store_unavailable"`，模型路由不受影响——spec 生命周期 Scenario）；`deps.Source == nil` 时经 `newKeeperStatsSource(cfg)` 构建（错误码 → error）。`context.WithCancel` + `wg.Add(2)` 起两个 goroutine 跑 `s.loop(ctx, s.scheduleTick)` / `s.loop(ctx, s.sendTick)`（`loop` = ticker select，`ctx.Done` 返回）；装配 `activeNotification.svc = s`。
- `(*notificationService).Stop(ctx)`：cancel → `wg.Wait()`（带 ctx 超时保护）→ 从 `activeNotification` 摘除 → `status.Running=false`。Stop 后不再有新 Claim；唯一在途任务的迟到结果经 Revision 检查与 `FinishJob` 的 sending 前置约束兜底（spec「迟到结果不能写入新配置」）。

`scheduleTick`（周期生成闸门核心，判重 = PeriodKey 天然去重）：

```go
func (s *notificationService) scheduleTick(ctx context.Context) {
	now := s.deps.Now()
	for _, binding := range s.state.KeyBindings {
		if !binding.Enabled { continue }
		for _, n := range effectiveNotifications(&s.state, &binding) {
			if !n.Enabled || n.Schedule == nil { continue }
			next, ok := nextTrigger(*n.Schedule, s.lastFire, NotificationLocation)
			if !ok || next.After(now) { continue }
			if err := s.enqueueForPeriod(ctx, &binding, n, s.deps.Store, now); err != nil {
				s.mu.Lock(); s.status.ErrorCode = err.Error(); s.mu.Unlock()
			}
		}
	}
	s.lastFire = now
}

- `enqueueForPeriod(ctx, binding, n, store, now)`：对 `n.Modules` 逐个非窗口模块 `s.deps.Source.collectForPeriod`（失败 → `controlled(err)` 写入 status.ErrorCode 并跳过该周期——已有存档不清空、失败不转零值）；窗口/重置卡素材经 `collectWindows`+`identifyAuthIndex` 补进 `statsData`；`renderMessage` 出文本后对每个 `Enabled` 平台 `UpsertJob`（`ID: newJobID()`、`KeyFingerprint: keyFingerprint(binding.Key)`、`PeriodKey: currentPeriodKey(n, now)`、`Revision: store.Revision()`、`NextAttempt: now`）。
- `sendTick(ctx)`：`supersededStaleJobs(store, store.Revision())`（`Revision < rev` 且 pending → `jobSuperseded`——spec 热重配丢弃）→ `ClaimDueJobs(now, 10)` → 逐 job：`ctx.Err() != nil` 即返回（不发起新发送）→ `s.deliverOne(ctx, j)` → `FinishJob(j.ID, res.Outcome, res.ErrorCode, res.Detail)`。
- `deliverOne`：按 job.Platform 重建 adapter（`deps.NewAdapter` 由测试注入替身），`adapter.send` 对 payload 拆片发送并合并结果：任一片 `deliveryUnknown` → 整体 unknown；`rate_limited` → failed + `RetryAfter` 写回 `NextAttempt`（经 UpsertJob 重入队退避）；全部 accepted → accepted。
- 辅助：`controlled(err)`（`*keeperError` → Code 字符串，否则 `"connection_failed"`）、`newJobID()`（UnixNano hex）、`currentPeriodKey(n, now)`（interval → `"interval:"+触发锚点`；日历类 → 第一个统计模块的 `periodKeyOf` 结果）。
```

其余按接口块补齐：`supersededStaleJobs(store, rev)`（Revision < rev 且 pending → jobSuperseded）、`controlled(err)`（`*keeperError` → 其 Code 字符串，否则 `"connection_failed"`）、`newJobID()`（UnixNano hex）、`currentPeriodKey(n, now)`（interval → `"interval:"+触发锚点`；日历类 → 第一个统计模块的 periodKey）。
