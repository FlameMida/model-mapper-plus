### 任务 17：合并与清理

**资源台账**（承载于 `plan/progress.yaml` 的 `resources` 键——规范定义点见「progress.yaml 键结构」节；行格式 `<类型>: <标识> —— <清理命令>`）；下方清理步骤遍历该清单。

progress.yaml 的 worktree 行在 T00 核实后记录实际路径、分支与归属；只给本计划创建且拥有的资源写清理命令，复用资源写保留/移交回执。

本任务必须写明适用的台账执行边界：只处理本计划拥有的资源，台账外不动，共享缓存默认保留，复用资源移交。

**步骤 1：全量验证（安全网）与归属裁决**

入口按实际 ID 逐个检查前序票（含 T00、实施票与验收票 T16）已完成，最终票自身应为 pending 或 in_progress，不能要求全表 completed 才进入本票。例如最终票为 T17 时，检查 T00—T16，不用 completed 总数代替 ID 对账；先保存本票 in_progress，实际收尾完成后才保存 completed。

在 worktree 内运行完整测试套件（不受「相关测试范围」约束）：

```bash
go vet . && go test -race ./...
npm --prefix web run typecheck && npm --prefix web test && npm --prefix web run build
```

- 全绿 → 进入步骤 2。
- 失败测试在相关测试范围内 → 修复并复跑全绿后进入步骤 2。
- 失败测试在范围之外 → 归属裁决：在主工作区的源分支检出上复跑该测试（主工作区有未提交改动 → 先询问用户）。源分支同样失败 → 报告"既有失败"，请用户裁决是否阻塞合并，不自行静默忽略；源分支通过 → 判定为本次引入的回归，修复并复跑全绿后进入步骤 2。

**步骤 2：测试退役检查**

扫描路径落在本计划「相关测试范围」内的测试，找孤儿测试：测试名对不上任何 active spec 的**现行** Scenario（现行=所在 Requirement 未被 `Superseded` 标注；判定基础是"测试名沿用 Scenario 名"约定，不合该命名约定的历史测试不进候选，保守豁免），且对应 Requirement 已 REMOVED、**或其标题下带 `Superseded` 标注**、或所属 spec 已 superseded——双条件缺一不可。候选清单非空 → 列清单征询用户，同意后删除并计入本任务提交；用户未确认则不删除任何测试。无候选 → 声明"无孤儿测试"后跳过。

**步骤 3：取代回写（spec 的 `supersedes` 为空——本 spec `supersedes: []`——声明"无取代回写"后跳过）**

本 spec 与四个 active spec 分面共存、不登记 supersedes；此步跳过。

**步骤 4：合并回来源分支**

从 T00 已保存的 notes 读取实际来源工作区、来源分支、实施工作区、实施分支及归属，生成读取、绑定和核验的完整命令。先在实施工作区提交收尾所需的 spec/状态变更并核实干净（`git status --porcelain` 为空），再在来源工作区核对当前分支和干净状态，最后用 `git -C` 在该路径合并实施分支：

```bash
# 1) 实施工作区：确认干净
git -C .worktrees/plan-2026-09-13-01-key-usage-notifications status --porcelain
# 2) 来源工作区（路径与分支读 T00 notes；不由 .git 目录位置推算）：
git -C <来源工作区绝对路径> rev-parse --abbrev-ref HEAD
git -C <来源工作区绝对路径> status --porcelain
# 3) 合并（来源工作区内执行）：
git -C <来源工作区绝对路径> merge --no-ff plan-2026-09-13-01-key-usage-notifications
```

合并冲突、或主工作区有未提交改动 → 停下向计划作者确认，不强行合并。复用或原生隔离将合并/清理交回原机制，不自行取得其资源所有权；此分支保留实际未合并状态与资源，等待原机制的真实交付回执后再做步骤 6 和最终完成；不能把"已移交"写成"已合并"。

**步骤 5：清理（按资源台账逐条执行）**

普通串行执行从已合并的来源工作区读取 progress 并执行清理。逐条核对台账归属与资源实体，执行本计划拥有资源的清理命令（当前台账仅 worktree 一行：`git worktree remove .worktrees/plan-2026-09-13-01-key-usage-notifications && git branch -D plan-2026-09-13-01-key-usage-notifications`）；worktree 与分支分开核对结果，不把部分成功写成全部完成。全部条目执行完毕后**一次保存**：成功条目移除、失败条目保留并整体记 blocked、已不存在条目核实后移除并记"已不存在"，notes 逐条追加真实结果；随后**一次提交**（`chore(T17): cleanup ledger`）。中途失败同样一次保存一次提交后停止后继锚定/完成。台账外的文件、容器、数据一律不动。

**步骤 6：sync_commit 锚定**

```bash
SYNC=$(git rev-parse HEAD)   # 已取得真实合并证据且核验通过的目标工作区 HEAD
# 将 spec frontmatter 的 sync_commit: null 更新为 $SYNC（保留其余键值）
git add .spec-dev/2026-09-13-01-key-usage-notifications/spec/key-usage-notifications-design.md
git commit -m "chore(spec): sync_commit 锚定 ${SYNC:0:7}"
```

此后 `git diff <sync_commit>..HEAD -- 'main.go' 'state.go' 'management.go' 'notification_*.go' 'web/src/**'` 即"spec 上次确认同步以来的代码变化"。

**步骤 7：最终状态保存（不因无 Spec 或非 Git 而省略）**

前面所有适用步骤实际完成后，在存活且符合现行写权限/绑定的工作区原子保存本票 completed、current=null 与实际验证提交 SHA，并独立提交；任何合并、清理、锚定或归档转换仍未完成时，保留相应等待/阻塞状态，不写 completed。
