### 任务 1：前端依赖升级 + 引入 dnd-kit

**文件**：
- 修改：`web/package.json`（依赖版本，以执行时 `pnpm view <pkg> version` 复核为准）
- 修改：`web/vite.config.ts` / vitest 配置（仅当 vitest 5 / jsdom 30 破坏性变更要求时）
- 测试：既有全部 `web/src/**/*.test.tsx` 作为回归基线

**接口**：
- 消费：无
- 产出：升级后的依赖基线——React 19.3、semi-ui 2.103（React19 adapter 已在 `web/src/main.tsx:5` 导入，无需改动）、dnd-kit core+sortable 可 import；T11+ 的组件任务在此基线上开发。

本任务是非行为任务（依赖升级）：无 TDD 五步，验证 = 升级后既有测试/typecheck/build 全绿。

**步骤 1：升级运行时依赖**

```bash
pnpm --dir web add react@^19.3.0 react-dom@^19.3.0 @douyinfe/semi-ui@^2.103.0 @douyinfe/semi-icons@^2.103.0 @dnd-kit/core@^6.3.1 @dnd-kit/sortable@^10.0.0
```

预期：安装成功，`web/package.json` 中六项版本 ≥ 上述下限。`pnpm view` 显示更高稳定版时取更高版（记录实际版本到提交信息）。

**步骤 2：升级工具链依赖**

```bash
pnpm --dir web add -D typescript@^7.0.2 vite@^8.3.0 @vitejs/plugin-react@^6.1.1 vitest@^5.0.0 jsdom@^30.0.1 @testing-library/react@latest
```

**步骤 3：全量前端验证（本任务的"红转绿"）**

```bash
npm --prefix web run typecheck
npm --prefix web test
npm --prefix web run build
```

预期：三条全部退出码 0。已知的可容忍变化：jsdom 30 对 `Element.prototype.animate` 的行为差异——项目已有 canvas shim 与 Select motion 禁用惯例（`web/src/test/setup.ts`），若既有组件测试因动画/时序 flaky，在该 setup 内修补而不是逐测试跳过。typecheck 因 TS 7 严格化报错 → 修类型（不加 `any` 豁免）；vitest 5 配置项更名（如 `environment` 沿用、`coverage` 提供方变化）→ 按官方迁移改 `vitest.config`。构建体积变化记录到提交信息（UI 内联单文件）。

任何既有测试在升级后语义性失败且非上述可容忍类别 → 停下向计划作者确认（可能是 semi-ui 2.103 行为变化，需要评估是否波及 T11+ 的组件选型）。

**步骤 4：提交**

```bash
git add web/package.json web/pnpm-lock.yaml web/vite.config.* web/src/test/
git commit -m "chore(T01): upgrade web toolchain to react 19.3/semi 2.103/vite 8.3/ts 7.0/vitest 5, add dnd-kit"
```
