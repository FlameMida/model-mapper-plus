**接口**：

- 产出（T10 前端契约）：
  - `GET /v0/management/plugins/model-mapper-plus/notifications/settings` → `NotificationSettings` JSON（**明文回显** Webhook/SignSecret——spec 2026-09-13 确认；完整 API Key 不在此响应）
  - `PUT .../notifications/settings` → body `NotificationSettings`；校验失败 400；成功后 `BumpRevision()` + `restartNotificationServiceWithState(loadedState)`；响应 = stateResponse（带 `audit` 元数据，走 `auditedStateManagement`）
  - `GET .../notifications/status` → `notificationStatus` JSON（含 `global_name`、`store_error`）
  - `POST .../notifications/preview` body `{"key":"", "notification_id":""}`（key 空 = 全局实体）→ `{"text","warnings":[...],"bytes":N}`——**用保存后的配置版本**渲染，不发送，不含秘密
  - `POST .../notifications/test-send` body 同 preview → 立即采集+渲染+发送，响应 `{"delivery_ids":[...]}`；走 `withAuditedManagement`（spec：测试发送纳入管理审计）
  - `GET .../notifications/deliveries?key_fingerprint=&notification_id=&platform=&outcome=&limit=` → `{"items":[deliveryRecord]}`
  - `POST .../notifications/deliveries/retry` body `{"id":"..."}` → 以原 delivery 的 payload 重新入队 pending，响应 `{"job_id":"..."}`

func mgmtRequest(method, path, body string) pluginapi.ManagementRequest {
	var raw []byte

	return pluginapi.ManagementRequest{Method: method, Path: path, Body: raw, Query: map[string][]string{}}

**步骤 3：写最小实现**

`notification_management.go`：每个路由一个 handler（模式照 `managementPutRules`），集中在：

```go
const notificationHandleBase = managementHandleBase + "/notifications"

func handleNotificationManagement(req pluginapi.ManagementRequest) (pluginapi.ManagementResponse, bool) {
	path := strings.TrimRight(req.Path, "/")
	switch {
	case req.Method == http.MethodGet && path == notificationHandleBase+"/settings":
		return managementNotificationSettingsGet(), true
	case req.Method == http.MethodPut && path == notificationHandleBase+"/settings":
		return managementNotificationSettingsPut(req), true
	// … status/preview/test-send/deliveries/retry 同形
	}
	return pluginapi.ManagementResponse{}, false
}
```

`management.go` 两处修改（旧 → 新）：
- `handleManagementRegister` 的 Routes 追加六条 `{Method, Path: managementRegisterBase + "/notifications/…", Description}`；
- `dispatchManagement` 的 `switch` 末尾、`return managementError(404, …)` 之前插入：

```go
	if resp, handled := handleNotificationManagement(req); handled {
		return resp
	}
```

`managementNotificationSettingsPut`：unmarshal `NotificationSettings` → `applyStateUpdate(func(st *State) error { st.Notifications = &body; return validateNotificationSettings(&body) })` → 成功后 `notificationStore().BumpRevision()` + `restartNotificationServiceWithState(loadedStateSnapshot())`；包装 `auditedStateManagement`。`managementNotificationSettingsGet`：`loadedStateSnapshot().Notifications` 为 nil 时返回零值默认实体；直接 `managementJSON(200, settings)`（明文）。preview/test-send：`effectiveNotifications` 选实体（key 空 = 全局；key 给定且无 id = 该 Key 第一条）→ 渲染；test-send 对每个启用平台 `buildAdapter(...).send` 并 `FinishJob` 落投递记录；`setNotificationStoreForTest`/`notificationStore()`：包内单例钩子（生产由 `restartNotificationServiceWithState` 打开并缓存，测试注入替身）。`Deliveries` handler 把 query 参数映射 `DeliveryFilter`（`limit` 默认 100、上限 500）。
