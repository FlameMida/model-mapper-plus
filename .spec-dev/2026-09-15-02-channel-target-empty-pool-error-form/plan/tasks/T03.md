### 任务 3：验收（acceptance-qa）

> 本任务由 executing-plans 收尾审查阶段触发 acceptance-qa 按下表执行，
> 不参与逐任务连续执行；报告与证据落盘特性目录 `acceptance/` 子目录。

| Scenario / 检查项 | 维度 | 执行方式 | 目标 | 阈值/预期 | 验收证据 |
|-------------------|------|---------|------|----------|---------|
| 宿主链路 429 透传到客户端（codex `/v1/responses` 协议路径） | integration | 冒烟：构建绑定 key 定向单一不存在于 candidates 的凭据，用该 key 发起 codex 请求 | CPA 宿主（docker，`CPA_SMOKE_BASE_URL`）真机 | HTTP 429；错误体 JSON 含 `error.code=auth_not_found`、可重试语义 `error.message`、`error.detail.candidates ≥ 1` 与 `error.detail.binding` 计数；无凭据 ID/供应商名/key 值泄露 | 冒烟输出 + `acceptance/` 报告 |
| 宿主链路 429 透传到客户端（Claude `/v1/messages` 协议路径） | integration | 同上构造，claude 格式请求 | 同上 | HTTP 429；错误体含 `error.type=auth_not_found`（Claude 协议断言 type）；detail/脱敏同上 | 同上 |
| host-version-compat 重跑 | integration | 按旧特性 `acceptance/host-version-compat.md` 的矩阵流程对新形态重跑（v7.2.119 为插件 go.mod 锚定版本；更高版本按文档既有实践追加） | 同上 | 各协议 429 断言通过；结果**追加**为新表（历史 503 表保留） | 更新后的 host-version-compat.md |

环境变量与前置：`CPA_SMOKE_MGMT_KEY`、`CPA_SMOKE_CLIENT_KEY`、`CPA_SMOKE_BASE_URL`（CLAUDE.md「Tunable variables」节）；需要运行中的 docker CPA（宿主侧预置至少一个可用凭据使宿主征询插件 scheduler）。真机不可用时如实记录未验证与缺口，不伪造通过。
